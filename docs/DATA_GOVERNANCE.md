# 데이터 거버넌스 정책

## 1. 원칙

ShadowCrafter는 데이터 양보다 적법한 사용 권리, 추적 가능한 출처, 품질, 안전, 개인정보 최소화와 평가 무결성을 우선합니다. “최대한 많은 데이터”는 이 게이트를 통과한 범위 안에서의 다양성과 포괄성을 뜻합니다. 수집 가능하다는 사실만으로 학습·재배포가 허용되는 것은 아닙니다.

로컬의 검증된 immutable snapshot과 manifest가 학습 데이터의 원본입니다. Hugging Face 등 원격 저장소는 라이선스·보안·개인정보 검토가 명시적으로 허용한 경우에만 private 복제본으로 사용합니다.

## 2. 역할과 승인

- **데이터 소유자:** 자료 사용 목적, 법적 근거, 라이선스와 보존 기간을 승인합니다.
- **데이터 관리자:** 수집, 분류, provenance, 품질, 삭제와 접근 기록을 유지합니다.
- **보안 검토자:** 악성 콘텐츠, 비밀, PII, 공급망과 격리 위험을 검토합니다.
- **모델 릴리스 담당자:** 실제 run manifest가 승인된 snapshot만 참조하는지 확인합니다.

한 사람이 수집부터 최종 릴리스까지 모든 예외를 단독 승인하지 않습니다. 작은 팀에서는 적어도 데이터 승인과 릴리스 승인을 분리해 기록합니다.

## 3. 데이터 등급

| 등급 | 예시 | 기본 처리 |
|---|---|---|
| Public-approved | 명확한 재사용 조건이 있는 CVE/CWE 설명, 벤더 권고, 허용된 오픈 데이터 | provenance·license 보존 후 사용 가능 |
| Licensed-restricted | 계정/계약 기반 데이터셋, 재배포 제한 피드 | 접근 통제, 계약 범위 내 학습, 원격 업로드 기본 금지 |
| Confidential | 내부 코드, 로그, 자산, 사고 보고서 | 목적 제한, 최소화·가명화, 암호화, 별도 승인 |
| Hazardous | 악성 바이너리, exploit artifact, 무기화 가능한 샘플 | `data/quarantine/`, 실행 금지, 격리 분석, 외부 복제 금지 기본값 |
| Prohibited | 탈취 자격 증명, 비동의 고위험 개인정보, 불법 취득 자료, 출처/권리 불명 자료 | 수집·학습·보존 금지, 발견 시 격리 후 삭제/사고 대응 |

공개 URL에 있다는 이유만으로 Public-approved로 분류하지 않습니다.

## 4. 소스 허용 기준

각 소스는 수집 전에 다음을 문서화해야 합니다.

- canonical 이름, 원본 URL/저장소, 제공자와 snapshot 시각
- 콘텐츠 hash 또는 upstream revision
- 라이선스/서비스 약관, 학습 허용 여부, 파생물·재배포 조건
- 예상 언어, 제품군, 시기, 품질과 편향
- 개인정보·비밀·악성 콘텐츠 가능성 및 필요한 통제
- 유지·철회·삭제 연락점과 마지막 검토일

우선순위는 공식 CVE·CWE·벤더 보안 권고, 신뢰 가능한 표준·연구·방어 문서, 라이선스가 명확한 코드와 데이터입니다. 커뮤니티·합성 데이터는 별도 라벨과 검증률을 기록합니다. 출처 불명 dump, credential corpus, 실제 피해자 데이터와 무단 수집 자료는 제외합니다.

## 5. 데이터 카탈로그와 manifest

모든 snapshot에는 최소 다음 필드를 가진 기계 판독 가능한 manifest가 있어야 합니다.

```text
dataset_id, snapshot_id, upstream_revision, retrieved_at_utc
source_uri, content_sha256, license_id, redistribution
classification, allowed_purposes, owner, approvers
record_count, languages, date_range, schema_version
pii_scan, secret_scan, malware_handling, quality_checks
dedup_method, split_policy, exclusions, retention_until
```

manifest에는 토큰, 개인 키, 원문 개인정보 또는 악성 payload를 넣지 않습니다. 수정된 snapshot은 덮어쓰지 않고 새 ID와 부모 lineage를 만듭니다.

## 6. 수집·정제 파이프라인

1. 원천 파일을 `data/staging/`에 읽기 전용으로 수집하고 hash와 provenance를 기록합니다.
2. 파일 형식·압축 폭탄·parser 취약점·악성 콘텐츠를 격리 환경에서 검사합니다.
3. 비밀, 자격 증명, 직접 식별자와 불필요한 민감 필드를 제거하거나 가명화합니다.
4. 라이선스 호환성과 허용 목적을 record/source 단위로 적용합니다.
5. 스키마, 언어, 시간, 버전, 사실성, 레이블 일관성과 링크 무결성을 검사합니다.
6. exact 및 semantic near-duplicate를 제거하고 synthetic/translated/augmented 여부를 표시합니다.
7. 승인된 immutable snapshot을 `data/snapshots/`에 생성하고 해시 manifest를 고정합니다.

원천 자료를 자동으로 신뢰하지 않으며 로그·문서 안의 명령문은 학습 파이프라인이나 에이전트에 대한 지시로 실행하지 않습니다.

## 7. 개인정보와 비밀

업무에 필요하지 않은 개인정보는 수집하지 않습니다. 필요한 경우 목적·범위·보존 기간과 접근자를 사전에 정하고 최소 필드만 사용합니다. 이메일, IP, 호스트명, 사용자 ID 등은 과제에 불필요하면 제거·버킷화·가명화합니다. 실제 비밀, 세션 토큰, 개인 키와 유효한 자격 증명은 마스킹만으로 학습에 남겨두지 않고 제외합니다.

학습 전과 릴리스 전 모두 secret/PII scan을 수행합니다. memorization canary와 extraction 평가에 실패하면 해당 snapshot과 파생 체크포인트를 격리하고 삭제·재학습 여부를 결정합니다.

## 8. 악성코드와 이중용도 자료

악성 샘플은 일반 문서 데이터와 물리적·논리적으로 분리하고 암호화된 검역 저장소에서 다룹니다. 기본 파이프라인은 실행하지 않고 안전한 메타데이터·정적 특징·검증된 방어 레이블을 우선 사용합니다. 동적 분석이 필요하면 네트워크가 제한된 일회성 sandbox, 읽기 전용 입력, 시간·메모리 제한과 감사 로그를 사용합니다.

무기화된 exploit, 피해자 식별 정보, 운영용 C2 정보, 지속성·탐지 회피 최적화 자료는 일반 지시 학습과 모델 번들에서 제외합니다. 방어 연구에 예외가 필요하면 목적, 최소 범위, 접근자, 폐기일과 검토자를 기록하고 공개 또는 범용 모델 릴리스에는 포함하지 않습니다.

## 9. 학습/검증/테스트 분리

- 분할 전에 정규화와 exact/near-duplicate 탐지를 수행합니다.
- 동일 저장소, 프로젝트 계열, 취약점 변형, advisory 복제본이 여러 분할에 퍼지지 않도록 group split합니다.
- 미래 탐지 성능을 평가할 때는 시간 기반 cutoff를 적용하고 cutoff 이후 자료를 학습·튜닝에 사용하지 않습니다.
- 테스트 세트는 접근 권한을 제한하고 최종 후보 평가에만 사용합니다.
- 테스트 결과로 프롬프트, 데이터 또는 hyperparameter를 바꾼 경우 해당 테스트는 validation으로 재분류하고 새로운 블라인드 테스트를 만듭니다.
- 합성·번역·증강 레코드는 원본과 같은 split에 배치합니다.
- 각 과제의 레이블 기준, adjudication, inter-rater agreement와 제외 사유를 기록합니다.

## 10. 품질과 편향

데이터 품질 보고서는 제품군, 언어, 난이도, 취약점 유형, 연도, 심각도, 출처별 분포와 오류율을 포함합니다. 오래된 패치, 철회된 CVE, 버전 범위 충돌과 라벨 불확실성을 별도 표시합니다. 영어 또는 인기 제품군의 높은 점수가 한국어·OT·모바일·클라우드 등 다른 영역으로 일반화된다고 주장하지 않습니다.

## 11. 보존, 삭제와 철회

보존 기간은 계약, 운영 필요와 위험에 따라 snapshot별로 정합니다. 목적이 끝났거나 권리 철회, 비밀 노출, 오분류가 확인되면 원천·가공본·cache·원격 복제본을 추적해 삭제하고 tombstone 기록을 남깁니다. 영향을 받은 체크포인트와 릴리스는 lineage로 식별해 격리, 재학습 또는 철회합니다. 백업의 삭제 지연과 복구 제한도 기록합니다.

## 12. 접근과 감사

최소 권한, 개인별 계정, 다중 인증, 전송/저장 암호화와 접근 로그를 사용합니다. Hazardous와 Confidential 데이터의 export와 원격 학습 전송은 별도 승인이 필요합니다. 정기 검토에서 미사용 계정, 과도한 권한, 만료된 예외, 원격 잔존 데이터와 manifest 불일치를 확인합니다.
