# ShadowCrafter 위협 모델

## 1. 목적과 범위

이 문서는 ShadowCrafter의 로컬 개발 환경, 원격 GPU 학습 환경, 데이터 공급망, 모델 artifact, private GitHub와 public Hugging Face 저장소, 추론 서비스와 SIEM/SOAR 연동에서 예상되는 위협과 통제를 정의합니다. 보안 보증서가 아니며 아키텍처·데이터·도구 권한이 바뀔 때 갱신해야 합니다.

공격 기법 평가는 대상 소유자의 명시적 허가를 받은 격리형 샌드박스로 제한합니다. 운영 환경에 대한 자율 공격과 악성코드 실행은 신뢰 경계 밖이며 지원하지 않습니다.

## 2. 보호 자산

- 소스, 학습 설정, 환경 lock, 데이터·모델 lineage
- Ornith 기반 모델과 ShadowCrafter 체크포인트·최종 가중치
- 원천·가공 데이터, CVE snapshot, 라이선스 증거, 악성 샘플
- 블라인드 평가 세트, 점수, 실패 사례와 안전성 평가 결과
- SSH 키, GitHub/Hugging Face/클라우드 토큰 및 SIEM/SOAR 자격 증명
- 고객 로그, 자산 정보, 사고 기록, IOC 및 생성된 비공개 보고서
- 코드·모델·평가 결과에 대한 Odytssey의 신뢰와 릴리스 무결성

## 3. 신뢰 경계와 데이터 흐름

1. **외부 자료 → 데이터 수집 구역:** 모든 자료는 신뢰하지 않은 입력으로 시작합니다.
2. **수집 구역 → 검역/정제 구역:** 라이선스, 악성 콘텐츠, 비밀, PII, 중복과 오염을 검사합니다.
3. **로컬 원본 → 원격 GPU:** 승인된 고정 manifest와 필요한 최소 데이터만 암호화 채널로 전송합니다.
4. **원격 GPU → 로컬 증거 저장소:** 로그·평가·checksum manifest만 회수합니다. 모델 weight는 로컬로 복사하지 않습니다.
5. **로컬 Git → private GitHub:** 소스·문서·소형 manifest만 push하며 비밀과 대용량 artifact는 제외합니다.
6. **원격 릴리스 → public Hugging Face:** 게이트를 통과한 비상업 9B 모델 번들만 전용 저장소에 복제하고 로컬 manifest로 검증합니다. 비공개 평가 증거와 데이터는 게시하지 않습니다.
7. **사용자/보안 도구 → 모델 → 도구 제안:** 입력과 retrieval 문서는 비신뢰 데이터이며, 모델 출력은 권한이 없는 제안으로 취급합니다.

로컬 PC는 소스·데이터·평가·manifest의 원본입니다. 모델 weight는 사용자 지침에
따라 원격에만 있으므로, 서로 독립적인 두 원격 사본과 복원 검증이 없으면
릴리스를 완성했다고 간주하지 않습니다.

## 4. 위협 행위자

- 금지된 공격 능력을 얻거나 안전장치를 우회하려는 외부 사용자
- 과도한 권한을 가졌거나 실수하는 내부 사용자
- 데이터·의존성·기반 모델·업데이트 채널을 변조하는 공급망 공격자
- 악성 로그, 티켓, 코드, 문서로 프롬프트 인젝션을 시도하는 입력 제공자
- 원격 학습 호스트 또는 계정을 침해한 공격자
- 모델의 한계로 인해 사실이 아닌 취약점·완화책·도구 명령을 생성하는 비악의적 실패

## 6. 도구 사용 정책

모델은 기본적으로 직접 실행 권한이 없습니다. 도구 호출이 필요한 경우 broker가 사용자·테넌트·대상 범위·작업 종류를 검증하고, 구조화된 allowlist 인자만 전달합니다. 임의 shell과 unrestricted network access는 제공하지 않습니다. 변경·차단·삭제·격리·자격 증명 작업은 별도 인증된 사람의 승인을 요구하고 모든 호출에 요청자, 모델 revision, 입력 근거, 결정, 결과와 rollback 상태를 기록합니다.

## 7. 원격 학습 통제

- 개인 SSH 키 파일을 저장소, 컨테이너, 원격 디스크 또는 로그에 복사하지 않습니다. 로컬 SSH agent나 승인된 단기 자격 증명을 사용합니다.
- 호스트 키를 신뢰 가능한 별도 채널로 확인하고, 전송 전에 목적지·계정·경로를 확인합니다.
- 원격 환경에는 해당 run에 필요한 최소 데이터와 토큰만 전달하고 공개 inbound port를 열지 않습니다.
- 기반 모델, 코드, 데이터, 환경 image를 digest/revision으로 고정하고 run manifest에 기록합니다.
- 결과 weight는 원격에서 hash, shard 완전성, 안전한 파일 형식과 평가 증거를 검증한 뒤 immutable 원격 release로 승격하며, 로컬에는 manifest만 회수합니다.
- 작업 종료 후 원격 토큰을 폐기하고 provider 정책에 맞춰 임시 데이터·볼륨을 정리했는지 검증합니다.

## 8. 검증 계획

각 릴리스 후보는 최소한 다음을 통과해야 합니다.

- 데이터 계보·라이선스·중복·오염 검사
- 독립적인 checksum 및 오프라인 로딩 검사
- 취약점/CVE/IOC 과제의 누수 없는 품질 평가와 캘리브레이션
- prompt injection, 비밀 추출, 학습 데이터 재현, 도구 오용 평가
- 금지된 악성코드·무단 침투 요청 거부와 허용된 방어 요청의 과도한 거부 평가
- 악성 artifact parser와 격리 경계 테스트
- SIEM/SOAR dry-run, 승인, idempotency 및 rollback 테스트

## 9. 잔여 위험

새로운 CVE, 불완전한 벤더 정보, 데이터 편향, 난독화, 적대적 입력과 생성 모델의 비결정성 때문에 오탐·누락·환각은 남습니다. 95% 게이트를 통과해도 특정 조직·언어·제품군에 일반화됨을 보장하지 않습니다. 따라서 출처 검증, 기존 스캐너·EDR·정적 분석기와의 교차 확인, 최소 권한, 사람 승인과 지속 모니터링이 항상 필요합니다.

## 10. 갱신 조건

새 데이터 공급자, 기반 모델, tool connector, 공개 배포, 멀티테넌시, 자동 실행 권한 또는 새로운 원격 학습 사업자를 도입하기 전에 이 위협 모델과 [DATA_GOVERNANCE.md](DATA_GOVERNANCE.md), [MODEL_RELEASE_POLICY.md](MODEL_RELEASE_POLICY.md)를 함께 재검토합니다.
